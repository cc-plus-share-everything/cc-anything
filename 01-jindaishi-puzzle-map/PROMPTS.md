# 提示词

中文 | [English](PROMPTS.en.md)

分两部分：这一期实际对 Claude Code 说过的话，以及按阶段整理好、可以直接复制去复刻别的视频的提示词。

## 一、实际说过的话

整条片子只用了下面几句，其余都是 Claude Code 自己推进的。

1. `下面开始复刻 基准：中华民族的救亡图存 这条视频，原版还原。写代码的形式还原`
2. （Claude Code 反问了四个选择题，全部选了推荐项）地图数据用阿里云 DataV；原片下载到本地仅供研究；老照片用维基共享公有领域；先做画面，声音后定。
3. `打开项目目录，我来看下`
4. `很好，基本已经复刻全了。音乐再配上去吧`
5. `还是有些瑕疵的，2.09左右，北平，部队入城的照片没有了`

能这么短，是因为项目里事先放了一份约束文件，每次开工都会被读到。

## 二、约束文件（放在项目根目录）

```text
# 视频制作约束

- 付费生成预算为 0：不调用任何付费的视频、图片、配音、超分服务。
- 画面全部用本地代码渲染（Blender / PIL / ffmpeg）。
- 没渲染完不要让我看片；渲染结束、完整解码检查过，再告诉我文件在哪。
- 下载任何文件、对外发布任何内容，先问我。
- 用到的外部素材（地图数据、照片、字体）逐项记录来源和授权。
- 别人的原片只用于研究对照，不进成片；原片的旁白、音乐不直接搬用。
- 如实汇报：没做完、没核实、和原片有差距的地方直接写出来。
```

## 三、分阶段提示词

把 `<…>` 换成自己的内容。可以一次全给，也可以一段一段给。

### 1. 拆解

```text
复刻基准是这条视频：<链接>。先不要写渲染代码，只做拆解：

1. 每秒抽 2 帧，每 8 秒拼成一张 4×4 联系表，逐张看完。
2. 用本地语音识别跑一遍音轨，告诉我有没有旁白、是什么音乐和音效。
3. 输出镜头表：时间段 / 屏幕上的标题 / 3D 画面在做什么 / 讲解卡和照片 / 字幕原文。
4. 列出画面要素：场景、物体、材质、动作、后期叠加层。
5. 判断原片大概是怎么做的，哪些在 3D 里完成，哪些是后期叠的。

写进项目 README。
```

### 2. 动手前一次问清

```text
开始制作前，把需要我决定的事一次问完，每项给出推荐项和理由：
数据来源、素材来源和授权、原片是否下载到本地、声音怎么处理。
我确认后记进 README，之后同一方案不要再重复问。
```

### 3. 数据和贴图

```text
准备地图数据：
- 省界之外，把前线会经过的省再切到地级市，每块是一片独立的拼图。
- 统一做等积投影，约定好「1 个单位 = 多少公里」，后面所有脚本共用同一套投影和范围常量。
- 边界适度简化，小岛不单独成块。

再用 PIL 生成贴图：每种势力一整张覆盖全图的旗面，拼图块按自身位置取其中一部分；
另做一张焦痕贴图（一个通道存深浅，一个通道存出现时间）和一张底盘底图。
每张贴图生成后导出一张小预览图，和原片截图对比。
```

### 4. 时间表

```text
把全片调度写成一个时间表文件，3D 渲染和 2D 后期都只读它：
- 翻面事件：起止秒、目标势力、选中哪些块、从哪个经纬度向外扩散
- 镜头关键帧：秒、看向的经纬度、距离、俯仰、方位；硬切点单独列出
- 标题、字幕、讲解卡、照片、战役浮标各自的起止时间和文字

时间以镜头表为准，按原片每 0.5 秒一帧去对。
```

### 5. Blender 场景

```text
写一个可以无界面运行的 Blender Python 脚本：
- 由轮廓生成带厚度的拼图块，顶面一圈描金倒角，侧面木色。
- 所有块共用一个材质，用物体自己的属性决定显示哪张旗面，不要每块一个材质。
- 翻面动作：抬起、翻转、落下，按离扩散中心的距离错开。
- 灯光跟随镜头目标，近景开景深，开运动模糊。
- 必须支持两种运行方式：只渲染指定几秒的低分辨率静帧；按帧范围渲染并跳过已存在的帧。
- 每帧导出关键地点在画面上的像素坐标，给后期用。

先渲染 4–6 个时间点的静帧给我自己核对，不要直接渲染全片。
```

### 6. 2D 后期

```text
用 PIL 写逐帧后期，多进程：调色、暗角、左上角标题、底部字幕、讲解卡、带白边的照片和图注、
战役浮标、落位火星。字体、字号、位置从原片截图上量出来，按输出分辨率换算。
素材缺失时用灰色占位，不要报错中断。支持只处理指定帧范围。
```

### 7. 对照迭代

```text
写一个对照脚本：输入若干时间点，把原片和复刻在同一秒的画面左右并排拼成一张图。
全片每 8 秒取一个点过一遍，列出差距，按影响大小排序，逐项改时间表或后期参数。
只重渲受影响的帧。每轮结束更新 README 的「已知差距」。
```

### 8. 全片渲染和交付

```text
静帧对照通过后渲染全片：分成两个进程并行，崩溃自动续跑。
完成后编码成 mp4，再出一个「左原片 / 右复刻」的并排版本。
检查总帧数、时长、能否完整解码，然后再告诉我文件路径。
```

### 9. 看片挑瑕疵

```text
<时间点> 左右，<哪里不对>。
```

例如：`2.09左右，北平，部队入城的照片没有了`。说清时间和现象就够，它会自己去对照原片那一秒，找素材、补上、只重做受影响的片段。

## 四、几条经验

- 第一句话就把「基准是哪条」「要还原到什么程度」「用什么形式做」说全。
- 约束写进文件，不要每次口头重复。
- 让它先出静帧再渲全片，能省掉大部分返工。
- 反馈瑕疵时给时间点，比给形容词有用。
